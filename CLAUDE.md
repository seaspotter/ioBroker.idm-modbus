# CLAUDE.md – ioBroker.idm-modbus

Local ioBroker adapter for IDM heat pumps (Navigator 2.0 primary, 1.7 / 10 later) over Modbus TCP.
**The source of truth for scope, register model, modules and the step plan is [docs/SPEC.md](docs/SPEC.md).**
Read the relevant section before implementing a feature; if reality (a device scan) contradicts the spec,
update the spec and register files afterwards, never the other way round.

- npm package `iobroker.idm-modbus`, adapter name `idm-modbus`, repo `seaspotter/ioBroker.idm-modbus`
  (`iobroker.idm` on npm is the unrelated cloud adapter).
- Sibling adapters to look at before inventing a pattern: `~/github/iobroker.openwb2` (TypeScript, closest
  template), `~/github/iobroker.victoriametrics` (HTTP client shape, jsonConfig), `~/github/iobroker.meterops`.

## Standing orders

### Safety – the real heat pump
1. **No write to the real device without explicit approval in the chat**, every time. Scan and read-only tests
   are allowed. Writes to EEPROM registers (marked `*` in the spec) need a separate, explicit OK naming the register.
   The user's own Navigator 2.0 heat pump on the LAN is the test device: **reading it for live verification is always
   allowed (standing order, 2026-10-10), writing never, unless the user explicitly lifts this order.** Its address stays out of the repo.
2. Never poll the device harder than the spec's throttling: one TCP connection, serial requests, pause between
   requests (default 100 ms). The Navigator stalls under hard polling.
3. Never put IP addresses, passwords or tokens into logs, exports, fixtures, commits or docs. Scan fixtures are
   committed **without** host/IP.
4. Never write test data to a production system of the user (lesson from victoriametrics: the user corrected this once).

### Register data and sources
5. **Source hierarchy (binding order).** Nothing about registers, types, ranges, enums or behaviour is written from memory.
   1. **Device scan** at the test device (always wins, then spec and register files are corrected).
   2. **The IDM documents in [docs/sources/](docs/sources/) are the binding documents** (see its README for the list and
      revisions): Modbus TCP Navigator 2.0 (812170 Rev.10), Navigator 10 (812663 Rev.0), and Navigator 1.0/1.7 (812049 Rev.1). Per family, the matching document is authoritative for that family.
   3. **Secondary source: Xerolux's work**, [idm-heatpump-api](https://github.com/Xerolux/idm-heatpump-api) and
      [idm-heatpump-hass](https://github.com/Xerolux/idm-heatpump-hass) (MIT). When the IDM documents are unclear,
      ambiguous or silent, look there before guessing. Where he disagrees with IDM, IDM wins, and the difference is
      recorded in the Step 2 deviation report.
   4. Other community sources (e.g. dschrempf/idm-modbus, forum posts) are comparison only.
   Every register entry carries `verified: doc | community | device` (`doc` = IDM document, `community` = Xerolux or other).
6. The code contains no addresses; only `src/lib/registers/*.json` (generated by `tools/build-registers.ts`) does.
7. **Credit Xerolux** wherever his work was used (README acknowledgements, register file headers, spec). No code or
   data copied from sources with unclear license (dschrempf/idm-modbus: comparison only). MIT sources (Xerolux) may be
   used with attribution. O10 (licenses) is resolved: dschrempf/idm-modbus is BSD-3-Clause but stays comparison-only; Xerolux (MIT, Copyright Basti) needs attribution incl. copyright notice.
8. The IDM PDFs live in `docs/sources/` for reference only; they are not part of the npm package (`docs/` is not in
   `package.json` `files`) and stay IDM's copyright. Do not rewrite or re-host their content as documentation; the
   register files contain facts only. The service password trick mentioned in the spec stays out of all docs.

### Process
9. Work step by step as in the spec's phase plan; a step is finished when its acceptance criteria hold
   (`npm run build`, `npm test`, `npm run lint`, `npm run check` all green). Do not start the next step silently.
10. **Do not commit, push, tag, publish to npm, or open PRs unless asked.** When asked to commit, end the message with
    the attribution line from the session's system reminder. No Sentry config without asking (deferred until the
    adapter is accepted into the official repo and gets the shared DSN).
11. Check for existing helpers and sibling-adapter code before writing new utilities. Read the actual sibling file;
    syntax and imports move on.
12. Ask only when a decision is genuinely the user's (scope, hardware risk, naming). Otherwise pick the sensible
    default, state it, proceed.
13. **Debugging:** for "it says success but nothing happens" ask early for the target's own log (Navigator GLT Monitor,
    ioBroker log at debug level) before theorizing from the client side. Always test the multi-item / batched case,
    not just a single register (victoriametrics lesson).

### Code
14. TypeScript, `strict`, CommonJS output via `tsc -p tsconfig.build.json` (TypeScript 7 native `tsc`; `build-adapter ts` cannot find it, see rule 30). JSDoc on every exported function and on non-obvious
    internals; comments explain *why* (device quirks, spec references like "O3/V4"), not what.
15. Constants (intervals, limits, defaults, `MAX_TIMER_MS`) in `src/lib/constants.ts`; user-configurable values only in
    `io-package.json` `native` + `src/lib/adapter-config.d.ts`. Recurring patterns (create state, decode value,
    write guard) go into helper functions.
16. Anything that talks to the outside (`src/lib/modbus/*`) returns `{ ok: true, ... } | { ok: false, error }` and
    **never throws past its own boundary**; errors are sanitized before logging (no host, no credentials).
17. Use the adapter's managed timers (`this.setTimeout` / `this.setInterval` and their `clear*`), never bare globals,
    including inside helper classes (pass the adapter's functions in). Clamp user-supplied timer values against
    `MAX_TIMER_MS`. `onUnload` stops everything in try/catch and **always** calls `callback()`.
18. A bad config entry disables that entry with a log message; it never crashes the adapter. A device that is
    unreachable at startup is a `warn` + reconnect with backoff, not a refusal to start.
19. Colocate tests as `src/**/*.test.ts` (mocha + chai via `@iobroker/testing`); pure logic (codec, batching, address
    formulas, write guards, source modes) gets unit tests with the spec's check values. No test may touch the real device.
20. Prettier/ESLint config is the ioBroker one (4 spaces, single quotes). Run `npm run lint` before declaring done.

### ioBroker conventions (each learned the hard way)
21. State roles must exist in the ioBroker role catalogue (`level.power` / `level.energy` do not; use `level` or
    `level.temperature` etc.). Create the **parent folder/channel objects** for every state path; no orphans.
    Verify the object tree against a live dev-server instance, not just unit tests.
22. `encryptedNative` / `protectedNative` belong at the **top level** of `io-package.json` (sibling of `common` / `native`),
    not inside `common`.
23. `adminTab.link` placeholders are `%protocol%` `%host%` `%port%` (no `native_` prefix).
24. `package.json` `keywords` is an **array** and must contain `"ioBroker"`; `io-package.json` `common.news` keeps only the
    last ~5 versions (older ones go to `CHANGELOG_OLD.md`); `nogit: true` is set because `build/` is not committed.
25. `eslint.config.mjs` ignores must use `**/build/**` and `**/dist/**` (bare `build` misses nested output and can hang lint).
26. README changelog uses a literal `### **WORK IN PROGRESS**` heading for the next version (not inside an HTML comment),
    entries as `- (SeaSpotter) text`. Run `npm run translate` after touching `io-package.json` news/desc or `admin/i18n`.
27. **English in the code, 11 languages for users** (user's standing order, 2026-10-10; this was the slow part in openwb2, so do it
    from the start). Source code, comments, log lines, error messages, tests, tool output and commit messages are English only.
    Everything a user can see - `jsonConfig` labels, `admin/i18n/*.json`, object and state names, `common.states` texts, `io-package.json`
    names/news/desc - exists in all 11 ioBroker languages (en, de, ru, pt, nl, fr, it, es, pl, uk, zh-cn). German for register
    texts stays the wording of the IDM documents. Mechanics: `src/lib/dictionary.json` maps every English text to the languages (filled by
    `npm run translate:strings` from `tools/sources/*.source.json` and `tools/sources/runtime-names.json`, which also syncs the
    `io-package.json` instance object names); runtime code uses `localized('English text', {vars})` from `src/lib/translations.ts`;
    admin texts go through `npm run translate`. `src/lib/translations.test.ts` fails when any language is missing, so a new text
    without translation cannot ship. The README is English (ioBroker requirement). `docs/SPEC.md` and the deviation report are German working documents, not product text.
28. `jsonConfig` cannot merge an async `sendTo` result into an editable table without clobbering user edits. If a
    feature needs that (scan suggestions), use the React admin pattern from `iobroker.openwb2` instead of hacking jsonConfig. That pattern is
    `@iobroker/gui-components` + React 19 + MUI 9 (openwb2 migrated off `@iobroker/adapter-react-v5`, which is in maintenance
    mode and pinned to React 18 / MUI 6, commit a0e0d2e); never start from the old adapter-react-v5 setup.
32. **Config baseline = `~/github/iobroker.openwb2`** (it already went through the official ioBroker.repositories checker, PR #6800).
    Before touching tooling or `io-package.json` settings, diff against that repo and take its newer value, and where the world has
    moved on further, go further (rule 30). Aligned 2026-10-10: create-adapter 3.1.5 output, `@iobroker/*` dev packages, keywords
    array, `nogit`, top-level `encryptedNative`/`protectedNative`, Dependabot cooldown, deploy job on Node 24. Minimums (user decision 2026-10-10, replaces the earlier "newest" order because the repository checker E4033 rejects versions
    that are not yet in the stable repository): `io-package.json` uses the current **stable** releases, `admin >=8.0.14` and `js-controller >=7.2.2`.
    Re-check with `npm view iobroker.admin dist-tags` / `iobroker.js-controller dist-tags` (field `stable`) at the start of every step. Intentional differences: Node 24 / TypeScript 7, no React admin yet.

### Dependencies
30. **Always the newest or close-to-newest version of every library, tool and runtime dependency** (user's standing order,
    2026-10-10, applies to really everything). Check `npm outdated` / `npm view` before adding a dependency and at the start of
    every step. **Any deviation (older major, pinned version, ignored update) needs the user's explicit OK first - ask, never
    decide alone.** Current stand: everything on latest except the user-approved `@types/node` 24 (= `engines.node`, TypeScript 7 via the side-by-side alias below). Prefer modern, maintained, TypeScript-native,
    few-dependency packages; no legacy Modbus libraries. The Modbus client is `modbus-connect` behind our own wrapper `src/lib/modbus/client.ts` (user decision, spec O11); only that file may import it.
    Decided 2026-10-10: TypeScript 7.0.2 with `@types/node` 24 and `engines.node >= 24`. TS 7 ships no JS API, so `package.json` uses the
    official side-by-side setup: `typescript` = alias of `@typescript/typescript6` (API for typescript-eslint, ts-node), `@typescript/native` =
    TypeScript 7 (`tsc`). Revisit when TS 7.1 brings the new API and typescript-eslint / `@iobroker/adapter-dev` support it, then drop the alias.
31. **Dependabot** (`.github/dependabot.yml`, from the scaffold) must be set up and enabled once the repo is on GitHub; its `ignore` rules
    must match rule 30 (the `typescript` ignore is removed; the `@types/node` ignore must follow the Node minimum, 24, and the `typescript` alias needs a Dependabot check). Open task, do not forget.

## Commands

| Command | Purpose |
| --- | --- |
| `npm run build` | compile `src/**/*.ts` to `build/` |
| `npm run check` | `tsc --noEmit` (types, incl. tests) |
| `npm test` | unit tests (`src/**/*.test.ts`) + package files test |
| `npm run test:integration` | starts the adapter against a js-controller test instance |
| `npm run lint` | ESLint |
| `npm run dev-server` | local ioBroker sandbox on port 8084 (`dev-server setup` first run). `dev-server watch default -n` syncs `build/` but **not `admin/`**: after changing `admin/jsonConfig.json` or `admin/i18n`, copy them into `.dev-server/default/node_modules/iobroker.idm-modbus/admin/` and run `.dev-server/default/iobroker upload idm-modbus`, otherwise the admin page shows raw i18n keys. Do not rebuild while a scan runs (the adapter restarts). |
| `npm run translate` | fill missing i18n languages |
| `npm run build:gallery -- <folder> [lang]` | draws every plant scheme of the IDM manuals (`tools/sources/diagram-schemes.json`) with the diagram page into `<folder>`; serve it statically, screenshots go to `<folder>/shots/<id>.png` (see `gallery.html`) |
